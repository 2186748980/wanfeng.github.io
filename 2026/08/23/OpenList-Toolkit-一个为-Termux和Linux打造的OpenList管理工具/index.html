OpenList Toolkit：一个为 Termux 和 Linux 打造的 OpenList 管理工具

日期：2026-08-23　作者：鱼

把 OpenList、aria2、AriaNg、Cloudflare Tunnel、备份、自启动和异常恢复等常用能力集中到一个轻量的命令行工具里。

为什么做这个项目

在 Android/Termux 和 Linux 上使用 OpenList 时，安装、更新、启动、查看日志、备份以及周边服务管理往往需要重复执行一堆命令。于是把这些操作集中到了一个交互式脚本中，希望打开一个菜单就能完成日常管理。

项目能做什么

  • 自动识别系统和 CPU 架构并安装/更新 OpenList。
  • 启动、停止、重启、状态检查和日志查看。
  • OpenList 数据备份与恢复相关操作。
  • 管理 aria2 和 AriaNg，并提供 RPC/Web 管理入口。
  • 通过 Cloudflare Tunnel 为 OpenList 提供外网访问入口。
  • 生成局域网访问二维码。
  • Termux:Boot 开机自启与 watchdog 异常恢复。
  • 同时支持菜单操作和非交互命令模式。

3.1：把 Toolkit 自更新改成 SHA-256 比较

这个版本比较重要的一处变化，是不再依赖固定的 TOOLKIT_VERSION 判断脚本是否需要更新。

本地 openlist.sh ── SHA-256 ──┐
                              ├─ 比较
GitHub main/openlist.sh ──────┘

本地脚本和 GitHub main 分支上的 openlist.sh 分别计算 SHA-256。两者一致就认为当前代码已经同步；不一致时再询问是否更新。

同时记录最近一次同步得到的远程 SHA-256。如果用户同步后又手动修改了脚本，自动更新会识别这种情况并避免直接覆盖自己的修改。

我比较看重的一点：不要把服务管理绑死

例如停止 OpenList 时，Toolkit 会询问是否同时停止 aria2 和 AriaNg。这样只是暂时关闭文件管理服务时，不会把正在运行的下载服务一起停掉。

Termux 场景

项目特别考虑了 Android/Termux 环境，会根据 uname -m 识别 arm64、arm、x86_64 等架构，并处理 Termux 存储权限、二维码生成以及开机启动等问题。

命令行模式

./openlist.sh --install
./openlist.sh --update
./openlist.sh --start
./openlist.sh --stop
./openlist.sh --status
./openlist.sh --backup
./openlist.sh --self-update
