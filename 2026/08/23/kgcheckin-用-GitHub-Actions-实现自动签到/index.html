kgcheckin：用 GitHub Actions 实现自动签到

日期：2026-08-23　作者：鱼

把每天需要手动操作的签到任务交给 GitHub Actions 自动运行。

项目思路

这个项目主要是一个 GitHub Actions 自动化实践：登录账号后，把必要的登录信息安全地放进 GitHub Secrets，再由 Actions 按计划执行签到任务。

目前的使用方式

项目提供二维码登录和手机号登录两种方式，其中二维码登录更适合普通使用场景。登录完成后，启用签到工作流，默认每天北京时间 01:10 自动运行。

为什么使用 GitHub Actions

最大的好处是不需要一直开着自己的电脑或服务器。仓库本身就是配置入口，Actions 负责按 cron 定时运行。项目还提供仓库保活工作流，避免长期无人维护时自动化任务停止。

Secrets 设计

GitHub Personal Access Token、酷狗登录 Token 等敏感信息不直接写入代码，而是保存到仓库 Secrets。项目中的登录信息会用于后续 API 身份认证，并支持定期刷新。

运行结果通知

项目可以选择配置通知渠道，包括企业微信、钉钉、飞书、云湖、Server 酱、PushPlus、Telegram、Bark、Discord 和 SMTP 邮件等。通知内容可以包含运行日期、账号数量、成功/失败统计、VIP 领取状态和错误信息。

一个值得注意的地方

这个项目依赖第三方 API 源码，并在仓库 README 中明确标注了来源和致谢。因此它更适合作为 GitHub Actions 自动化与 API 调用的学习实践，而不是把第三方接口包装成自己的原创 API。

安全使用

  • 不要把 Token、验证码或账号信息直接写入仓库。
  • GitHub PAT 只授予当前 Fork 仓库需要的最小权限。
  • 使用第三方 API 时应遵守相关平台规则和版权要求。
  • 项目仅用于学习、研究和技术可行性探索。
